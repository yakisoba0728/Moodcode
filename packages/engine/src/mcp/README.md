# MCP 엔진 경계

공식 규약을 확인한 독립 JSON-RPC 어댑터이며 OpenCode/SDK 구현을 복사하지 않았다. 신규 dependency는 없다. 기본 pin은 2026-07-28이며 2025-11-25를 명시하면 legacy initialize/session 규약을 사용한다. 지원하지 않는 버전은 거부한다. 자동 era fallback·자동 도구 재실행은 없다.

- McpClient({id,transport,protocolVersion,requestTimeoutMs}) → connect(signal) → listTools/listResources → callTool/readResource → close. modern은 server/discover와 매 request의 _meta, legacy는 initialize 이후 initialized notification을 사용한다. 참고: [versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning), [discovery](https://modelcontextprotocol.io/specification/2026-07-28/server/discover), [legacy lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle).
- StdioMcpTransport는 absolute executable/cwd와 명시 argv만 시작하며 shell을 사용하지 않는다. 기본 환경은 PATH 및 필요한 Windows SystemRoot만 전달한다. stdout newline JSON frame은 1 MiB 제한, stderr는 보관 없이 drain한다. 취소 notification과 pending request의 고유 ID를 사용하며 late response는 무시한다. 종료는 stdin close → POSIX group TERM/KILL이며 부모가 먼저 종료해도 같은 소유 group을 정리한다. Windows descendant cleanup은 이 backend가 보장하지 않는다. 참고: [stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio).
- HttpMcpTransport는 HTTPS 또는 explicit loopback HTTP에서 JSON/SSE POST를 지원하고 redirect와 URL credentials/query/fragment를 거부한다. modern은 version/method/name과 정형 x-mcp-header를 body와 일치하게 투영한다. invalid annotation의 도구만 제외한다. legacy는 session header와 close 시 bounded DELETE를 사용한다. modern 취소는 해당 request를 abort하고 legacy는 별도 cancel notification도 보낸다. SSE/전체 response는 합산 1 MiB 제한이다. broken stream/oversized frame/wrong ID는 connection과 catalogue를 무효화한다. legacy GET notifications/replay/resumption은 아직 제공하지 않는다. 참고: [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http), [legacy transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).
- registerMcp(client,runtime,signal)는 mcp_<id> scope에 이름을 disambiguate해 등록한다. runtime.setIncludedScopes('engine',[scopeId...])는 host가 명시적으로 노출할 scope를 선택한다. 서버 annotation의 readOnlyHint를 실행 권한으로 신뢰하지 않고 모든 remote tool은 unknown effect/approval이다. disconnect/list_changed는 disposer로 scope를 제거해 기존 catalogue/prepared/approval을 stale로 만든다. 주기 polling이나 modern subscriptions/listen은 아직 없으므로 재발견은 host가 명시 호출해야 한다. 참고: [tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools).
- schema는 bounded JSON object/정형 header annotation까지 검증한다. 전체 JSON Schema 2020-12 input/output 의미 검증기는 아직 없으며 argument validation은 서버도 수행해야 한다. 반환 text와 structuredContent를 분리하고 non-text block은 모델 text에서 생략한다. resource URI는 연결된 catalogue의 정확한 항목만 RPC로 읽으며 URI를 파일 접근이나 fetch 권한으로 해석하지 않는다. text/blob content는 bounded JSON 계약에 들어간다. 참고: [resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources).
- 샘플링·roots·elicitation·MRTR·Tasks·MCP Apps·OAuth UI는 지원한다고 광고하지 않는다. modern input_required 결과는 명시 unsupported 오류로 반환한다. legacy server request에는 지원하지 않는 host capability 응답을 보낸다. stdio 시작 또는 raw HTTP 실패가 이미 완료한 server effect를 취소/복구했다고 간주하지 않는다.

CredentialBroker는 host:<id>와 exact audience만 보관 인터페이스로 받으며 resolve/refresh callback을 호출한다. 계정 파일과 환경 키를 직접 읽지 않는다. authorization은 transport callback에서만 사용할 수 있고 broker JSON/inspect는 값을 숨긴다. host 오류 메시지는 sanitization한다. renderer/journal/command 환경에 token을 전달하는 API는 없다. host callback/transport 코드 자체는 신뢰 경계이며 JavaScript 문자열의 물리적 zeroization은 제공하지 않는다. 외부 OAuth 인증과 계정 UX는 후속 범위다.

검증: MCP 15개(실제 modern/legacy stdio child + loopback HTTP JSON/SSE, 취소/timeout/invalid/oversize/process group/session cleanup/header/resource/stale lifecycle), plugin 6개, credentials 5개가 source 및 compiled dist에서 통과했다. fixture credential만 사용했으며 실제 계정 조회나 외부 MCP 서비스 요청은 하지 않았다.
