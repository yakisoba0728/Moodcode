Moodcode now has an opt-in PR feedback lane through `prFeedback: true` with `verificationTools: true`. The feature includes the actual host API, a GET-only GitHub adapter, native SHA-bound history, bounded polling and trusted-host webhook signals, atomic queue acceptance, a real coding Run and native local verification. The default tool catalogue is unchanged. A CI pass or review approval never grants merge, comment, push or publication authority.

`previewPrWatch({ sessionId, watchId, repository, policy, config, sourceRunId, apiBase? })` captures an opaque Original registration preview. The preview fixes the physical workspace/storage binding, Root epoch, repository/PR identity, exact required check policy, normalized profile/model/catalogue and Run budget, plus an optional genuine prior verification/source manifest. `readPrWatchPreview` returns descriptive data. `registerPrWatch(original, { workspaceId, sessionId, watchId, requestId, expectedRevision: 0, previewSha256, decision })` needs that exact Original and explicit approval; denial is durable. Copies, accessors, stale source or configuration cannot enable a watcher. Exact registration duplicates return native history before requiring another Original.

The adapter uses unauthenticated public GitHub REST GET requests for the PR, its head repository's exact commit check-runs and statuses, and the PR reviews. It reads the PR again after bounded pagination and refuses mixed base/head/repository observations. Check identity includes provider, kind, name, app and run/status ID. Latest numeric run IDs supersede prior attempts independently of response order; missing, pending, failed and passed remain distinct. A historical check high-water mark prevents a later older green response from replacing an observed rerun. All current-head review bodies remain quoted data. Comments and unrelated dismissed reviews do not erase a changes-requested decision; a later substantive approval or dismissal of the particular review can resolve it. Older-head reviews are excluded. These are feedback semantics, not GitHub branch-protection or merge eligibility calculations. The adapter follows the [official check-run API](https://docs.github.com/en/rest/checks/runs), [status API](https://docs.github.com/en/rest/commits/statuses), [review API](https://docs.github.com/en/rest/pulls/reviews) and [review decision guidance](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/reviewing-proposed-changes-in-a-pull-request).

`pollPrWatch` and `reconcilePrHead` accept an exact watch revision and request identity. `acceptCiFeedback` accepts a trusted host's bounded webhook delivery ID/event as a lookup hint; it always obtains a fresh HTTP snapshot and never trusts webhook payloads as check outcomes. Stable delivery and semantic keys deduplicate polling, repeated events, reordered deliveries and restart retries. Repeated delivery IDs remain historical even after the caller's cursor advances. `startPrWatch` creates an explicitly started bounded loop; `stopPrWatch`, disable, cancellation and Root close stop its real HTTP work. No loop resumes automatically after restart.

HTTP pagination gaps, changing head during observation, obsolete check IDs, outage and rate limiting are explicit native gaps. A retained old green snapshot does not clear a gap. Rate-limit backoff avoids further requests before the recorded deadline. GET responses are cancelled on early 304/403/429/error/size-limit exits as well as streamed success/failure paths. Redirects and credential-bearing endpoints are refused. Production supports only `https://api.github.com`; loopback HTTP requires the separate explicit host opt-in used by actual fixtures.

A failed check or changes request can create a repair input only when the approved source Run has genuine terminal verification pass receipts, its bounded source manifest matches the clean local Git HEAD/files and the current remote PR head, the original check registrations and verification policy remain current, and the watch's exact repair allocation is available. Clean means no tracked or staged change anywhere in the repository; untracked files outside the pinned source paths do not count. Without that local source pin, feedback remains advisory and cannot enter a coding Run. The Root rechecks physical binding, profile, catalogue, configuration, current feedback/head and source before promotion, then checks the exact actual promoted input/Run and remaining original pins before every provider dispatch. Own changes made inside the admitted repair Run are allowed; external stale source before its first dispatch is refused.

The fixed input prompt quotes CI/review text as `untrusted-ci-review-data`. It contains the source manifest SHA, prior source Run, remote base/head and approved budget, but has no command override or publication grant. The host-approved normal coding profile and native tool approval pipeline still control effects. The repair Run uses the exact registered model/profile and ordinary measured Run ceilings. `getPrRepairVerification` joins its actual terminal Run, latest local verification plan/source, allowed native approval, Tool, terminal ToolPart, command checkpoint and cleanup/output evidence. It reports `verified-local` only for real current local passes; its `mergeAuthority` is always false and it does not turn the original remote CI failure into a remote pass.

Native storage reuses bounded SessionDocuments under `pr.watch.*`, `pr.feedback.*` and `pr.input.*`. Independent immutable registration, full watch-transition, actual HTTP-observation, feedback and native input-accepted events preserve the exact source, policy, target, request, cursor, allocation, prompt and accepted input tuple. Graph validation checks CAS/head replay, the exact repair counter, independent source/HTTP anchors, native input fingerprint/header/body/accepted birth and reverse input links. Metadata bounds apply before JSON bodies are fetched. Rehashed mutable documents, false green transitions, erased allocations, appended media and missing/aliased input links fail validation. No table or database version is added.

Snapshot, occurrence, cursor, allocation, actual input acceptance and full receipt/link are written synchronously in one primary transaction. Scheduler wake is registered only after COMMIT. A write failure rolls all of them back; actual SIGKILL before COMMIT leaves no input, while SIGKILL after COMMIT retains exactly one input and receipt. Reopen never repeats HTTP acceptance or creates another Run. Import preserves original history and pauses both watchers and feedback receipts; it cannot restore Original runtime authority or promote the historical pending input as a new repair.

The lane bounds global watches to 32, feedback occurrences to 128, reserved documents to 512/16 MiB with 128 KiB rows, immutable PR events to 2048/32 MiB, HTTP response bodies to 1 MiB, pagination to four pages, check observations to 256, reviews to 128 and prompts to 32 KiB. Each approved watch admits at most eight distinct repair inputs and uses its explicit ordinary Run budget. Limits produce conservative gaps or reject atomic admission before publication.

The accompanying verification artifact records actual temporary Git repositories, Engine verification/tool approvals, loopback HTTP servers, native queue/provider/repair consumption, SQL faults, socket cancellation, actual SIGKILL and genuine archive import. A separate unauthenticated public GitHub GET probe observed an actual PR base/head/check/review snapshot without any account, key, model request or write. Private repositories/authentication, public webhook ingress/signature verification, rule-set/branch-protection discovery, reviewer permission-based merge decisions, inline review-comment/annotation expansion and publication remain unsupported. The focused tests validate the supported lane; combined whole-repository gates belong to the integration parent after applying the feature patch.
