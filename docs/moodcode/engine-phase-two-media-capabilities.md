# Bounded media segments and provider outputs

This increment implements bounded native decoder/consumer paths for MC2-16b/c and an explicit local capability/output lane for MC2-16d. MC2-16d remains in progress: local fixture model declarations and wire tests do not verify an actual audio/video/output account or production model. It adds no database migration: DB23 remains at 139 catalogue entries, below the existing 160 cap. No account credentials or live model requests were used.

## Implemented paths

- `engine.importMedia(sessionId, bytes, mimeType, segments, signal?)` imports immutable, session-owned source bytes. `input.accept`/`run.submit` accept `media` references, and native admission, promotion, frozen context, latest-source history and retry dispatch retain those exact references. Every dispatch reopens and checks the physical blob and owner before the provider receives bytes.
- PCM16 RIFF WAV supports mono/stereo and 8/16/24/48 kHz. Selected integer millisecond intervals become actual new WAV files containing exactly those samples. RGB24/BI_RGB AVI supports one video stream and extracts actual, lossless PNG pixels with source frame timestamps; this is a frame projection, not a native full-video API. RIFF padding/layout follows [Microsoft WAVEFORMATEX](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex), [AVI RIFF layout](https://learn.microsoft.com/en-us/windows/win32/directshow/avi-riff-file-reference) and [BITMAPINFOHEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapinfoheader).
- Chat Completions consumes WAV `input_audio` and video-derived `image_url` blocks. Standard Responses consumes video-derived `input_image` blocks. Every asset is accompanied by quoted advisory DATA carrying the immutable source/asset SHA and timestamps. Audio input/output and video frames each require an exact provider model-ID declaration and the corresponding explicit `ModelSpec.mediaCapabilities` boolean. Generic modality labels or unknown model names never grant this support.
- Chat streamed output accepts one bounded PCM16 stream with an explicit host-selected voice, sample rate and channel layout. The host must verify the layout for its selected endpoint/model; the engine does not infer Chat PCM rates from the separate TTS API. It validates the ID, canonical base64, sample alignment, finish/DONE and final expiry, including the documented expiry update after `finish_reason`. Wire behavior follows [OpenAI audio Chat guide](https://developers.openai.com/api/docs/guides/audio-chat-completions) and [stream delta.audio schema](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events).
- Actual provider Attempt/Turn/Run ownership creates the generated Artifact and media Part. A discriminated provider Artifact identity has no fabricated Tool ID. Source admission, current Part revisions and genuine provider cleanup are independently checked against native journal rows and SQL owner columns. Artifact publication followed by a failed native receipt leaves uncertainty; it cannot become a successful completion or automatic retry.
- `getMediaCapabilities(providerId, modelId)` reports exact effective support and unknown token cost. `readMediaOutput({sessionId, partId, offset?, limit?, signal?})` is a host-only bounded read of native provider media history. It verifies the native source and managed Artifact; it never executes or restores a provider grant.

## Bounds and recovery

Each source is at most 512 KiB; source selection is at most four nonoverlapping intervals of at most ten seconds each within a thirty-second source. Each input has at most four source occurrences and four decoded assets, with a combined 1 MiB wire media budget. AVI dimensions are at most 256×256, with at most 32 source frames and 256 RIFF chunks. A session stores at most 32 immutable source references/16 MiB. Global native index admission caps 128 sessions/1 MiB of metadata, and native input-reference history caps 4096 rows per source table/16 MiB of total reference metadata. Provider media history caps 4096 Parts/16 MiB, with 512 bytes reserved per open Part for its immutable terminal revision. Capacity failures roll back the native transaction; indexed source publication is removed when its admission fails. Streaming output has at most 256 copied chunks, 512 KiB including its WAV header, thirty seconds, and consumes the same actual Run output budget as text. Native output reads default to 8 KiB and cap at 64 KiB.

Audio/video token cost remains `null`; textual estimates explicitly exclude decoded media cost. `allowUnknownMediaTokenCost: true` is a fixed host opt-in, independent of exact model support. Missing provider usage stays absent rather than becoming zero.

Cancellation, partial output, missing sources, stale owner/hash, unknown capability, invalid MIME/container/codec, oversized selection and byte/backpressure limits fail without substituting source bytes. Partial audio is an interrupted Artifact and a failed/interrupted Part. A partial sample is retained as raw octet data rather than mislabeled WAV. Transport cancellation must actually join; unresolved physical cleanup keeps native uncertainty.

Open/recovery/archive validation checks immutable input owners/references, provider Attempt/Part/cleanup/birth journals, manifests and real source/output bytes, including owned child archive members. Export/import preserve history and pause imported sessions. No imported model declaration or historical record grants live ownership. SIGKILL before final settlement leaves recovery required and never replays a provider; genuine completed history stays completed.

## Evidence and remaining scope

The independent source and compiled suites each pass 26 cases, including actual Engine→provider input/output, exact PCM/PNG pixel decoding, cancellation, unjoinable transport cleanup, SQL admission failure after physical publication, actual 128-session index capacity/rollback/reopen, Codex unsupported-media rejection before credential filesystem access, foreign native history, Artifact paging/integrity, archive/import and four actual SIGKILL boundaries. Adjacent source suites pass 282 and 191 cases; compiled adjacent suites pass 416 cases. These are overlapping regression selections, not additive unique counts. Final native inbox/record/Codex source and compiled selections each pass 71 cases. Whole-project declaration emission is clean. The accompanying verification JSON records commands, log hashes, source hashes and the isolated dependency aliases.

MP3/AAC/Opus/FLAC, compressed AVI/MP4/MOV, native full-video transport, image/video generation and Anthropic/Responses/Codex audio are unsupported in this increment. Codex image behavior is preserved; existing live-account evidence was not reclassified or reused as audio verification. GUI integration and account-level audio/Anthropic/PDF compatibility, unknown token economics and environmental E5-13 evidence remain open.
