# Next MC2-10 implementation slices

The atomic delivery and actual Run-owned command observation slices are now implemented in [the atomic/command increment](engine-phase-two-atomic-command-jobs.md). That implementation reuses existing native CAS SessionDocuments with independent immutable source/process/closed/document anchors, so the proposed DB23 extension below was not needed. Independent host approval/lease and explicit background ownership transfer remain planned. The original plan below records the prior design constraints.

The user-terminal watch and advisory queue lane are implemented and verified in [the jobs increment](engine-phase-two-jobs.md). MC2-10a/b/c/d remain in progress. The three implementation agents inspected the actual Runner, command, storage and scheduler boundaries while the final regression ran. This plan records their constraints; it does not claim that the following features are implemented.

The next independent storage slice makes completion delivery atomic. A Root-private ORIGINAL input port should call the actual native input storage inside the same synchronous primary transaction as the settled completion and delivery receipt. `NativeSessionStorage.write` already joins an outer transaction. `SqliteStore` needs a narrow post-commit callback queue: successful COMMIT publishes events and wakes `InputScheduler`, while ROLLBACK discards those callbacks. Calling the current `InputScheduler.accept` inside that transaction would start scheduling too early. There must be no await inside the transaction. Independent INSERT/COMMIT faults must prove completion, pending input and acceptance receipt are all present or all absent, with zero wake on rollback. A restart after successful COMMIT must inspect that same input rather than accept again.

The smallest command consumer slice observes a genuine `run_command` while its existing Run remains live. `prepareCommand` binds the canonical cwd, timeout, workspace, actual Run and tool-call fingerprint. `delegateCaptured` owns the ORIGINAL prepared tool and catalogue/profile/policy/preflight checks. Runner supplies the genuine Turn/Attempt/Tool, exact approval, budget and cancellation. Its native Tool completion and before/after checkpoint must still finish before the Run becomes terminal. Detach releases observation, and cannot transfer physical ownership away from that Run.

Root adds private observations only at actual command preparation, approved execution, before spawn, supervisor admission/output/close and native Tool/checkpoint settlement. A serialized context, PID, output path or invented Run is not evidence. The command supervisor, original process group execution lock, output limits and existing artifact store remain the physical producer. Native command-job states distinguish prepared/approved/dispatching/running/settled/uncertain and preserve intent or cleanup gaps without replay. A DB23 schema extension must discriminate this owner from the existing user-terminal source and preserve DB22 history; the fixed two-table storage can be extended rather than creating a second anonymous execution graph.

A separate idle-workspace host command requires its own original host approval, job owner, budget, checkpoint and workspace lease. Pure command preparation and physical execution can be factored into a neutral executor consumed by both adapters. Host execution cannot fabricate ToolContext/Run/Attempt records or reuse a Run's approval as indefinite background authority. The current `withWorkspaceLease` refuses active Runs, so a Run-owned command cannot acquire it recursively. Parent-terminal-independent execution needs an explicit durable ownership-transfer contract before it is enabled.

Parallel ownership for the next implementation is Root for actual Runner/command hooks and post-commit storage/input wiring, A for command source/output/artifact validation, B for native journal/migration/archive and atomic-receipt invariants, and C for the actual observer/host consumer and Engine fixtures. Each lane should freeze before final integration gates. Actual tests need denied/stale approval with zero spawn, canonical cwd/profile/catalogue changes before launch, Run/host lease competition, real detached observation, bounded output/backpressure, exact artifacts, cancellation and lost supervisors, root SIGKILL, EPERM/cleanup uncertainty, SQL intent/checkpoint/receipt failures, restart/import without respawn, and single admission after committed completion. Existing user-terminal watch uncertainty must remain isolated from unrelated workspace coding Runs.
