# PTY termination diagnostics

`engine.terminals.get(id, owner).diagnostics` and `engine.terminals.replay(id, owner).terminal.diagnostics` expose bounded, historical observation data. The same optional record is saved in the existing terminal SQLite sidecar and state attachment event. No migration, command approval change, or live process capability is introduced. Existing journal rows without diagnostics remain readable.

The version 1 record distinguishes the native node-pty exit from the supervisor process exit. `supervisorExit.closeObserved` states whether Node actually delivered its `close` event; an exit/EOF observation is recorded separately. Native exit codes and numeric signals are kept as observed, including `0` or `null`. `source.terminalPid` is the original native PID. `source.originalGroupPid` remains `null` until the actual ancestry snapshot verifies that group; probe event targets are recorded independently.

The record includes the final native outcome, bounded cleanup result events, error codes, ancestry snapshot availability and group sample truncation. It does not add command arguments, environment values, credentials, paths or output text. Diagnostics allow at most 16 KiB, 32 events and 32 sampled groups. Event loss is counted. Private collector overflow drops diagnostic detail while preserving the original process outcome; untrusted result and stored diagnostic payloads use strict descriptor-safe parsing.

The new IPC-close correction addresses an independently reproduced Node 26 case: the original supervisor exited, stdout reached EOF and IPC disconnected, but Node did not deliver `close`. Only the missing-result path with all three actual observations converges on the existing `supervisor_lost` result. Existing group cleanup still runs, and `cleanupConfirmed` remains false because supervisor loss cannot reconstruct separate job-control groups. The convergence and normal `close` paths settle once. Queued original IPC frames receive an event-loop turn to drain; late frames cannot replace a settled terminal outcome. Supervisor stderr remains ignored, so no stderr EOF observation is claimed.

Diagnostics do not grant execution or restore physical ownership. Imported or reopened terminal history still cannot produce a live Original source. ESRCH alone establishes group absence; EPERM remains unknown and conservatively present. Missing ancestry, unknown cleanup and supervisor loss retain their original uncertainty rules.

Focused source tests cover a genuine Engine PTY with stdin/resize/normal exit, SQLite persistence and restart history, actual cancellation, supervisor disconnect and SIGKILL, corrupt genuine supervisor result delivery, late delivery, bounded collector loss and hostile parser inputs. Pure parser tests are portable; actual PTY tests retain the existing supported POSIX qualification. They do not qualify Windows Job Object support.

The historical hosted `R-PTY-01` normal-exit uncertainty remains unexplained. This change collects the evidence needed for a future occurrence and fixes the separately reproduced IPC-close delivery issue; it does not reclassify that historical failure.
