# Native user-terminal observation jobs

`jobs: true` opts the actual Root Engine into observing an existing user-owned terminal. Children start with jobs disabled. This MC2-10 increment supplies native observation and completion delivery; MC2-10a/b/c/d remain in progress because approved engine-owned command execution, its workspace lease and complete crash/detach protocols are still open. Verified completion remains 38/80 work items and 8/20 families. The overall goal stays active.

The host calls `captureTerminalJob({workspaceId, sessionId, terminalId})`, inspects its detached DATA with `readTerminalJobSource`, and passes the ORIGINAL handle to `attachTerminalJob`. The physical terminal entry, birth nonce, real launch, current journal descriptor identity, Root storage/root identity and current owner epoch stay separate from serialized history. Replaced journal files, copied handles, wrong session owners and restored terminal history cannot grant a new source. Native DB22 adds two STRICT WITHOUT ROWID tables, immutable revisions and CAS heads. Session observation events anchor source, output and closed outcome without inventing a Run or appending to a terminal Run.

`captureJobOutput(originalSource, {jobId, jobRevisionId, cursor?, maxBytes?, maxFragments?})` uses the immutable `sourceRevisionId` from the attached job. `readJobOutputPage` returns DATA; `recordJobOutput` records the original page with a new output ID, request ID and expected job revision. Pages contain at most 8KiB raw UTF-8, 64 fragments and 64KiB encoded JSON. Exact byte offsets preserve UTF-8 codepoints. A cursor continues its original frozen snapshot while later output arrives. Without a cursor, the host resumes the persisted position; after its snapshot EOF it captures newer bytes. Ring eviction produces an explicit missing range. Native history rejects skipped prefixes, page replay, pages without progress and cursor reset. Snapshot retention is bounded to 64 snapshots and 16MiB encoded bytes; sources and host handles have separate finite caps.

`settleTerminalJob(originalSource, {workspaceId, jobId, requestId, expectedRevision})` requires the original actual PTY closed outcome and matching durable sidecar. SQL failure rolls back its source-closed anchor together with the native settlement. Missing cleanup confirmation or interrupted state preserves uncertainty. `cancelCommandJobWatch` retires observation alone. The existing user terminal retains its user input authority and its normal host lifetime; a watch never starts, writes, resizes or physically cancels it, adopts it as a model tool, or takes a workspace execution lease. Consequently, watch uncertainty blocks delivery but does not quarantine unrelated coding Runs.

After genuine settled cleanup, the host selects `captureCommandJobDeliveryTarget({workspaceId, jobId, config})`, inspects `readCommandJobDeliveryTarget`, and explicitly calls `deliverCommandJobResult({workspaceId, requestId, expectedRevision:0, target:original, approved:true})`. The result is a quoted advisory observation containing outcome and cursor metadata; output pages remain separate read-only history. The native intent, synchronous actual InputScheduler queue acceptance and native acceptance receipt are distinct durable steps. The stable request ID and original target prevent a second acceptance. A gap after acceptance remains uncertain and blocks promotion/reaccept until a supported explicit reconciliation protocol exists. This is not a single atomic transaction across all three steps.

Promotion and every actual provider dispatch recheck the authentic accepted input and its config/profile/catalogue/physical pins. A normal reopen may explicitly resume that already accepted native input without reconstructing a PTY or delivering again. Interrupted watches become uncertain. Imports preserve immutable history but pause jobs and deliveries; even `jobs:true` grants no source restoration, target rebind, automatic input acceptance or execution replay. History APIs remain available with jobs disabled: `getCommandJob`, `inspectCommandJobs`, `readCommandJobOutputs`, `inspectCommandJobDeliveries`. `releaseCommandJobHandle` and Engine close release retained observation handles.

The actual PTY cancellation regression now observes descendant job-control process groups before terminating the shell and confirms those observed groups are absent. A killed supervisor or failed process observation preserves `cleanupConfirmed:false`. This remains host-user POSIX process supervision; deliberately detached processes after lost ancestry are outside its observation contract. Linux/FreeBSD and unavailable PTY hosts retain explicit capability boundaries, and the real validation environment for this increment is Darwin arm64.
