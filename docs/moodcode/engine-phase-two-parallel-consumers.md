# Command, PR and workflow consumers

This batch integrates three complete features delivered by independent agents, then tests the shared native lifecycle in the main Engine. The actual integration fixture starts an approved independent host process, proves its physical lease blocks PR HTTP polling, cancels and confirms its PID cleanup, admits one host result and one PR result, and consumes both in different genuine subsequent Runs. The PR repair executes an ordinary command and the registered native verifier with jobs enabled.

Command model tools consume host-selected same-session original PTY, Run-owned and independent host aliases. Actual native Tool/Part publication, frozen UTF8 pages, explicit output loss and bounded source/snapshot memory are retained. Repeated unchanged polling uses one original snapshot instead of retaining another handle on every model tool call. Independent host result receipts bind actual native approval/process/closed evidence to the exact new input, full target config and current profile/catalogue, without inventing a source Run or Tool.

PR feedback uses actual public readonly GitHub GET. The unauthenticated public probe and independent HTTP fixture evidence are preserved in the feature report. Snapshot and required check/review state belong to an exact PR head/base. Native dedupe/cursor/gap/backoff and bounded repair inputs never turn old green into remote merge authority. Actual source and verification receipts gate the local repair; API error bodies are cancelled so streaming error responses do not retain sockets. Every webhook hint causes a fresh readonly request.

Effectful workflows run real separately persisted editor and validator child Engines. Ordinary exact approvals produce native patches, checkpoints and genuine verification. The parent uses a separately approved actual `merge_workflow_stage` ToolContext, source/artifact/HEAD/preimage pins and the existing child merge adapter. Effect receipt and stage CAS share a transaction; actual result acceptance shares its native input, receipt and independent birth event before scheduler wake. Physical merge without its terminal native receipt retains uncertainty, even when the changed bytes are present.

The new joint fixture exposed a real existing combination bug: jobs authenticated only the original command ToolContext, while verification executed its nested command using a bounded copy. The Root integration now authenticates that narrowed context from the original current approved verification execution only for the duration of the actual command. Copied outer contexts, unauthenticated nested copies, output widening and Proxy contexts cannot supply execution authority; the nested authentication is discarded on return or failure. Verification still owns its native Tool, checkpoints and receipt. The ordinary PR repair command retains its own real command job.

An earlier PR-only broad source gate found one existing fault fixture asserting PID disappearance immediately after a rejected native settlement. A native publication failure is uncertainty, not a physical exit acknowledgement. The fixture now waits for actual ESRCH, retains the final PID assertion and keeps every native uncertainty/restart/import check. Final compiled and broad source gates retain actual physical cleanup assertions. The first combined compiled gate also exposed an older stage-settled crash observer freezing inside the newly atomic stage/effect transaction. It now forwards that original transaction and freezes after its COMMIT, preserving every committed-boundary assertion; all four original crash cases pass in both compiled and source forms before the final whole rerun. The earlier failed gate remains recorded rather than being treated as passing evidence.

The final verification report records one immutable source snapshot across contracts, Engine and harness; whole compiled regression, broad direct source regression including verification, three scripted coding tasks, typecheck and actual DB23/DB22 catalogue observations. Feature-only patch hashes preserve each agent's delivered source identity. The newer resident-team, OS-sandbox and coding-batch work continues in separate worktrees, so its changes cannot invalidate this gate.
