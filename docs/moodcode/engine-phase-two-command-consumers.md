# Command job model consumers and independent host inbox

This increment consumes real command observations across the existing user PTY, Run-owned command and independent host command lanes. It does not start commands through a model read grant or transfer a command out of its original owner.

## Readonly model consumption

Opt in with `jobs:true, commandJobModelTools:true`. The fixed catalogue contains `read_command_job` and `read_command_job_output`. A trusted host separately calls `bindCommandJobModelTools({workspaceId,sessionId,profile:{id,revision},jobs:[{alias,kind,jobId,source?}]})`. The three source kinds are `user-terminal`, `run-command` and `host-command`; PTY selection requires its already attached ORIGINAL terminal source, while the two command kinds capture the existing private producer's ORIGINAL output reader. The source session must equal the consuming session. The exact registered profile must expose both tools. Child engines explicitly disable this feature.

Model input is only a bound alias and, for output, an optional cursor. Actor, session, workspace, job identity and execution authority are not model arguments. Preparation and execution authenticate separate genuine active ToolContexts against the native Run/Turn/Attempt/Tool, original advertised catalogue, current profile and role policy. The preparation actor must equal the execution actor. Copies, Proxy/accessor contexts and stale grants cannot read data. Normal tool budgets and Tool/Part publication remain owned by the actual Runner.

Pages use an ORIGINAL frozen source snapshot, source/native snapshot digests, bounded stream fragments with full-event raw SHA256, explicit lost ranges, and exact UTF-8 `{eventSeq,byteOffset}` cursors. Cursor checksums are descriptive DATA; the private binding/freeze maps provide authority. New output does not change an existing frozen cursor. Pages contain at most 8 KiB raw bytes and 64 fragments; the serialized envelope also fits the current tool output allowance and 64 KiB limit. Low output allowance fails before snapshot capture. There are at most 32 selected sources, 64 frozen snapshots and 16 MiB frozen encoded DATA in one Root. Repeated latest reads reuse an unchanged snapshot and release the fresh Original immediately. Release/close releases native handles. No source output/closed event is fabricated by model observation; only the consuming Run receives Tool/Part results.

## Independent host result inbox

The explicit public APIs are `captureHostCommandJobDeliveryTarget`, `readHostCommandJobDeliveryTarget`, `deliverHostCommandJobResult`, `getHostCommandJobDelivery`, `inspectHostCommandJobDeliveries` and `releaseHostCommandJobDeliveryHandle`. Capture requires `hostCommands:true, jobs:true`, a retained current actual host source, current sealed artifact identities, and completed/failed/cancelled state with confirmed cleanup and no observation failure. Running, uncertain, restored or imported source history cannot create a delivery Original.

The signed delivery target pins a compact settled observation to the actual independent native closed revision/full-job digest/owner/preview/PID tuple. The full independent command evidence stays in DB23 host command revisions and its native approval/process/checkpoint/cleanup journal. There is no invented Run, Tool, Turn, PTY or new migration. The receiving queue target independently pins full normalized configuration, registered profile, effective tools, catalogue/capabilities, workspace binding and fixed allocation. Source execution grants are not reused.

Delivery requires explicit approval of that ORIGINAL target. The prompt is at most 32 KiB of quoted advisory DATA, including source identity, state/outcome, checkpoint digest/counts and sealed-stream byte/truncation metadata. It contains no command text, cwd or absolute artifact paths. `executionAuthority:false` describes the observation; any later tool effect requires its ordinary current policy and approval.

An existing primary transaction commits the actual native queued input, full delivery receipt, input link, immutable `host.command.result_admitted` birth and document anchors together. Scheduler wake is deferred until COMMIT. SQL failure rolls them all back and does not wake a provider. Stable job/result and input request identities reject conflicting or second admissions; duplicate responses are copies of the first receipt. The reserved `host.command.delivery.*` / `host.command.input.*` documents are limited to 128 receipts, 256 documents, 16 MiB total and 128 KiB per row.

Promotion and every provider dispatch validate the actual native input/header/birth, full prompt/config, promoted Run identity/session/workspace/request, current target profile/catalogue/capabilities and no attachments/documents. A normal restart can explicitly resume already accepted input with the same target pins; it cannot reconstruct a source Original or rerun the command. Default-off runtime blocks consumption while allowing validated inspection. Archive/recovery validation independently checks these documents against actual independent command and native input journals. Import marks receipts `paused-import` and preserves immutable birth/link history; it restores no source grant and performs no replay.

## Verification

Focused source tests use the absolute tsx loader and real Engine, committed Git workspace, SQLite, user PTY/Node processes, native command approval and provider iterators. They cover all three source kinds, actual Tool/Part consumption, alias/profile/role/current owner checks, copied/accessor/Proxy inputs with zero traps, frozen UTF-8 pages and explicit loss, source reader failure cleanup, output limits, completed/failed/cancelled host inbox, native rollback/backpressure, artifact inode drift, receipt/link evidence, current profile and dispatch tuple drift, restart/import quarantine, and actual SIGKILL before/after COMMIT. Existing Run-owned inbox, ordinary command and terminal consumer regressions run separately. Whole-project `tsc -b` also checks declarations.

Foreground/background owner transfer and explicit host checkpoint restoration remain outside this increment.
