# MC2-07c/d: actual workflow effects and parent result consumption

The supported lane is complete from a host-registered workflow through genuine editor and validator child Engines, separately approved parent file application, native result admission and a real consuming parent Run. It uses the existing DB 23 workflow tables, SessionDocument CAS, native Tool/Part/approval/checkpoint records and InputScheduler. No migration or second scheduler is introduced.

## Actual supported path

1. Enable `workflows: true` and `verificationTools: true` on the root Engine. Register an explicit parent profile containing the workflow tools and the core handlers needed by the selected stages. Register native verification checks before starting the parent Run.
2. Create managed worktrees before the parent acquires its execution lease. Register a pinned workflow and use the existing Original `previewWorkflowStart` / approved `startWorkflow` APIs. Stage count remains eight and dependency depth remains four; `all` and first accepted `any` dependency selection retain the existing native CAS behavior.
3. Editors inherit the actual parent profile and model and narrow their available handlers to read tools and `apply_patch`. Each actual patch requires its ordinary exact native approval and produces a checkpoint. A directly dependent validator can explicitly use that same worktree after the editor releases its child lease. Unrelated or concurrent stages cannot share it.
4. Validators inherit that same configuration. A validator must pin a host verification policy `{ checkIds, sourcePaths, maxRepairs: 0 }` and expose `verify_changes` and its engine-owned `run_command` producer. Root registrations are copied with the working directory mapped into the actual child worktree; model-supplied commands or alternative profiles are not substituted. The genuine verifier runs through the child native tool/approval/artifact/checkpoint path.
5. Host `bindWorkflowModelTools({workspaceId, instanceId})` binds one Original workflow to its actual live parent Run. The fixed tools are `request_workflow_stage`, `observe_workflow_stage`, `merge_workflow_stage`, and `deliver_workflow_result`. A model can select a stage of this registered instance, but cannot select an actor, instance, workspace, model, profile or arbitrary execution scope. Stage dispatch, merge and delivery require their own exact native approvals. Observation is read-only.
6. Child completion captures genuine native Run, SessionSnapshot, Tool, Turn, Attempt, Tool Part, cleanup, checkpoint and verification evidence before the child Engine closes. The stage join and effect receipt commit together. The structured stage result remains advisory DATA. Failed native checks or failed child effects mark the workflow failed; they produce no successful effect, merge or result receipt.
7. `merge_workflow_stage` uses its original current Runner ToolContext and the existing approved child-merge patch adapter. Preparation pins the editor files, validator source/artifacts, native check registration and parent HEAD. Execute revalidates those pins and parent file preimages. A durable intent precedes physical application; the merged receipt is published only after the actual native Tool and completed Tool Part plus complete checkpoints exist. Parent merged file identities and hashes are then pinned for result capture and later input admission.
8. `deliver_workflow_result`, or host `captureWorkflowDeliveryTarget` / approved `deliverWorkflowResult`, admits one bounded quoted result with fixed queue-target config, profile, catalogue and budgets. Actual `store.acceptInput`, the signed result SessionDocument and the independent native event with its real input ID share one primary transaction. Scheduler wake occurs after COMMIT. The provider receives that queued DATA in a real subsequent Run; child text or metadata never grants replay, file effects, tool authority or approval.

## Host APIs and history

The new public APIs are `bindWorkflowModelTools`, `releaseWorkflowModelTools`, `captureWorkflowDeliveryTarget`, `readWorkflowDeliveryTarget`, `deliverWorkflowResult`, `releaseWorkflowDeliveryTarget`, `inspectWorkflowEffect`, and `inspectWorkflowDelivery`. Existing workflow registration/start/stage/observe/inspection APIs remain the host entry points.

Inspection returns history. Copied, released or restarted handles cannot regain Original authority. A successful instance child-join state and its effect state are separate: an instance can have completed structured joins while an editor effect is still `observed`. A result requires every editor effect to be `merged` and every validator effect to have genuine passing native verification. `merge-dispatching` and `uncertain` are workspace blockers, not completed effects.

A repeated request returns an immutable copy of the prior native result and never accepts another input, starts another child, resets reservations or reapplies the patch. Changing the registered spec, native stage revision, physical worktree, selected source, required check, parent HEAD/preimage, target profile or tool catalogue invalidates the pending effect at the appropriate boundary.

## Recovery, import and limits

Root restart never reconstructs workflow actor or child execution handles, restarts a child, reapplies a merge or automatically reaccepts a result. Interrupted native stages become uncertain. A physical merge without its final native receipt remains uncertain even if the bytes changed successfully. Before result COMMIT there is no input or delivery receipt; after COMMIT exactly one accepted pending input and receipt remain. An accepted local result can be consumed after explicit session resume when its historical target and physical source pins are still current.

Full engine archive/import preserves immutable stage/source IDs and hashes, child history and accepted input identity. Imported workflows, effect records and deliveries are paused history. Import grants no actor, child, target or execution handle. Source terminal Runs receive no new execution events from host result admission; result evidence belongs to independent Session events and its native input.

This lane supports core, bounded ordinary UTF-8 create/update patches and real engine-owned verification. Deletion, executable/custom-mode files, symlinks, missing/incomplete artifacts, unconfirmed cleanup, alternate model/profile escalation and custom ToolDefinitions as effect producers are rejected before granting the corresponding effect. Parent and child allocations use the existing reservation accounting; role labels do not increase them. Workflow result text is capped at 32 KiB, file observations at 32 paths of at most 1 MiB each, and native effect/delivery rows at 128 KiB together with the stricter existing immutable-JSON structural limits. Model-context and queued input limits still apply.

Standalone GUI/host merge execution without a genuine approved ToolContext is not supported. Hosts approve the actual parent `merge_workflow_stage` native approval. There is no constructed context or implicit approval bridge.

## Verification

The compiled tests run against actual Engine instances, temporary Git repositories, separately persisted child Engines, real approved patches and Node verification processes. The focused gate includes 18 new actual effect/consumer cases, five real Root SIGKILL boundaries and 40 existing workflow specification/native/host/archive regressions. The declaration-only check traverses the production engine index. No account credentials, external provider, source loader, replayed command or fake ToolContext is used.

Crash boundaries cover actual child completion, native stage transaction before COMMIT, physical parent merge before its final receipt, result acceptance before COMMIT and accepted result COMMIT before scheduler wake. Additional cases cover exact approval denial/cancellation, files/artifacts/HEAD/preimages/check registrations/profile drift, failed verification, Original/copy/accessor rejection, native receipt CAS faults, atomic SQL rollback, immutable duplicates, explicit restart resume, archive pause and a re-signed native receipt alteration.
