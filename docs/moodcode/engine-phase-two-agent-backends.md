# Owned ACP v1 agent backends

`agentBackends: true` enables explicit root-host registration of local stdio agent providers. Isolated child engines keep this option disabled. The supported lane is ACP v1 text prompts and native client file reads, with Moodcode owning context, budgets and approvals. Protocol v2, HTTP remote hosts, agent-owned context, session load/reconnect, remote permission grants, client writes and terminal effects remain unsupported. Recognized advertised capabilities for unused features negotiate to false; unsupported invocations/media and unknown capability fields produce errors before a client effect starts. This is a compatibility subset, not a claim of complete ACP support. The [official v2 migration](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/protocol/v2/migration.mdx) documents the different client-effect and prompt-completion contracts.

The host captures an original target with `captureAgentBackendTarget`, reads its inspectable pin with `readAgentBackendTarget`, and passes the original handle to `registerAgentBackend`. Its dynamic provider ID is `acp:<backendId>`. The target fixes the actual workspace/database/artifact/root identity, normalized Run configuration and all budgets, profile revision, full effective tool catalogue, capabilities, launch tuple, source-file hashes, endpoint audience and secret references. Copied pins do not reconstruct runtime authority. Existing host provider IDs cannot be overwritten. Registration and disable use native revision CAS and exact request-preimage dedupe.

The executable must be an exact regular real path, at most512MiB. Up to32 explicitly selected source files are fixed by inode, time, length and SHA256, with8MiB per file and32MiB total. File and configuration freshness are checked after awaited context preparation and immediately before the native provider dispatch intent. Each original Attempt can consume only one actual launch. Environment values come only from an explicit runtime resolver for configured references; the resolver/launch values are not serialized in backend configuration or native launch records. A peer can return data in its protocol/output, which is journaled; this lane does not guarantee redaction of peer-echoed secrets. Inherited peer environment and protocol credential authentication are not enabled.

An IPC supervisor launches the actual peer without a shell, owns its process group and execution lock, and cleans it when the engine disconnects. A fresh bounded initialize/new/prompt exchange belongs to the original native Run/Turn/Attempt and request SHA. Native `backend.launch_reserved` and `backend.connection_admitted` observations bind the exact actual connection ID, epoch, PID and birth nonce to that owner. The latter observation and connection receipt commit or roll back together. Prompt acceptance, ACP terminal response, process disposal, pipe delivery and durable receipt settlement are separate observations. EOF, a v2 acknowledgement, iterator return or a cancel acknowledgement cannot manufacture remote completion.

`fs/read_text_file` uses the still-open original provider request. The bridge executes the existing native `read_file` pipeline in the same Attempt: budget reservation, physical workspace scope, prepared fingerprint, role/tool policy, exact approval or deny, lifecycle checks, native Tool/Part settlement and output accounting. A native `tool.prepared` observation fixes the requested path/range before approval. Lifecycle input transforms that change a client read's path or range are rejected before preparation; ordinary model tool transforms retain their existing behavior. Parallel or repeated client identities cannot start a second read.

Only complete, untruncated native content at most24KiB is returned as a successful ACP read. Admitted partial paging, oversized content, denied reads and failures remain actual native outcomes and produce ACP errors. Their full native output digest and byte count remain recorded even when no content is sent. A budget/path/owner rejection before native Tool admission may produce neither a completion receipt nor an ACP response; its prepared client intent/request remains uncertain. The response write receives its own original pipe-delivery receipt. A missing delivery or uncertain cleanup blocks successful request settlement.

DB21 adds `backend_revisions` and `backend_heads`, two STRICT WITHOUT ROWID tables. Immutable backend, connection, request, client-effect and transition records use bounded headers, original producer proofs, revision CAS and actual native Run/Attempt/Tool/Part/approval references. Semantic graph checks reject self-consistently rehashed false terminals, foreign genuine owner relinking, changed prepared fingerprints, epochs, heads or receive ordinals. The actual SQLite catalogue has134 rows within the existing160-row inspection cap. DB20 history and failed migration rollback are preserved.

`getAgentBackend`, `inspectAgentBackends`, `inspectAgentBackendConnections`, `inspectAgentBackendRequests` and `inspectAgentBackendEffects` remain available when the feature is disabled. `releaseAgentBackendTarget` releases an original target. Disable removes new runtime provider admission while retaining observation authority for a previously dispatched request. Engine cancel/close stops admissions and cleans owned processes, retaining an uncertain remote request if no authentic terminal arrived. The strict protocol module validates `session/cancel`, but the current runtime stops the process rather than transmitting that wire notification. Missing native connection/disposal receipts also keep Attempt cleanup uncertain after physical process termination.

Restart converts interrupted backend execution to uncertainty and blocks new workspace work. Physical cleanup by the supervisor after an engine SIGKILL does not prove remote task completion. Archive import disables definitions, appends paused-import history and restores no runtime providers or original handles. Genuine completed imported history preserves its terminal/delivery/cleanup without inventing uncertainty; interrupted, unclean or undelivered imported effects retain quarantine. Inspection, reopen and import never replay a prompt.

[Verification](engine-phase-two-agent-backends-verification.json) records the frozen implementation and actual Engine/Git/SQLite/stdio tests, including root SIGKILL, reopen/import, SQL admission rollback, exact approval/deny, late cancellation, source drift, duplicate Attempt launch and lifecycle path/range rewrite rejection. MC2-09a/b are complete in this supported local lane. MC2-09c/d remain in progress for effectful permission/write/terminal integration, remote hosts, context ownership modes and reconnection. The original80-item goal remains active; GUI and live account calls are separate work.
