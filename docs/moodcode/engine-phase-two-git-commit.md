Moodcode now exposes host-approved Git commits through `gitCommits: true` with `verificationTools: true`. MC2-13a/b/c/d are implemented for bounded regular-file selections in an existing, non-bare repository on a supported POSIX process-group platform. The default tool catalogue is unchanged. This feature has no model tool, account connection, push, reset or automatic commit replay.

`previewGitCommit({ sessionId, requestId, runId, paths, message, selection })` returns an opaque Original handle. `readGitCommitPreview(handle)` returns its descriptive copy; changing or copying that data cannot approve an effect. The preview pins the physical workspace and storage binding, Root epoch, repository/git/common-directory identities, HEAD and symbolic branch, full real index bytes, selected blob/mode/source bytes, exact message, expected tree, configured Git/hook sources, required verification receipts and an explicit bounded execution allocation. Messages are approved with their final newline. Git signing is disabled and message cleanup is verbatim for this initial lane.

The selected source must be covered by the host's existing verification scope. Every required check in the latest plan must have a genuine pass at the current source. Independent SQLite validation joins the terminal Run, exact allowed verification approval, actual native Tool, terminal ToolPart, `tool.completed` cleanup/output evidence and real command checkpoint. A model statement, copied success record or a rehashed session document does not replace those facts. A stale staged blob that differs from the physically verified file is rejected.

`commitReviewedChanges(handle, { workspaceId, sessionId, requestId, previewSha256, expectedRevision: 1, decision: 'allow' | 'deny' }, signal?)` records the exact approval or denial and revalidates before dispatch. The workspace coordinator lease and existing persistent command execution lock cover supervision, Git/hooks, physical cleanup and native settlement. The child supervisor strips provider credentials and inherited Git overrides, owns each process group, and stops/joins it on cancellation, timeout or Root IPC disconnect. Native admission faults after supervisor readiness retain the lease until the actual supervisor exits and the lock is inspected. A process-admission write failure remains uncertain rather than becoming a successful cleanup receipt.

A temporary alternate index contains HEAD plus only the chosen files. `selection: 'staged'` commits verified stage-zero blobs and leaves the complete real index bytes unchanged. `selection: 'working-tree'` commits the exact verified working bytes, rejects overlapping user stage, and updates only the selected index entries after successful commit; every unrelated staged entry is preserved. Symlink/submodule selections, unmerged selected entries, empty selections, active merge/cherry-pick/revert/bisect state, unborn HEAD and bare repositories are refused before commit. A changed HEAD, index, source, message, selection, configured hook content or hook permissions invalidates approval. Hooks run normally; a real rejecting hook produces a failure receipt.

`git.commit.<request digest>` uses existing native SessionDocument CAS. Independent immutable source, full transition, supervisor, process-group and closed-observation session events retain the original approval and actual outcome. No new table or database version is introduced. Each receipt includes the actual commit SHA and observed parent/tree/message, process exit/cancellation/timeout/cleanup, and before/after Git/index/selected-file checkpoint data. Descriptive historical receipts never reconstruct an Original runtime handle.

A lost receipt after the actual commit leaves the durable dispatch intent quarantined. Restart changes interrupted approval/dispatch to `uncertain`, without executing Git or entering a provider. `reconcileGitCommit({ workspaceId, sessionId, requestId, expectedRevision })` is an explicit readonly operation: it checks the physical binding, inactive effect lock, absent admitted supervisor/process group and current Git parent/tree/message/index/source. It can record the exact already-present commit or confirm unchanged HEAD as a failed attempt; it never calls commit again. Foreign HEAD, hook-modified message/tree or conflicting index/source keeps the uncertainty visible. Those conflicts need explicit human resolution; no reset is offered.

`getGitCommitReceipt` and `inspectGitCommitReceipts` remain readonly when execution is disabled. Duplicate exact requests return immutable historical copies before requiring a fresh Original and never invoke Git. Imported heads become `paused-import`, retain their full original source/outcome and cannot resume execution from that history. A recovery-paused imported session cannot create a fresh preview.

The native ledger admits at most 64 records, 128 KiB per record and 8 MiB of current records; immutable Git events are bounded to 8192 rows and 32 MiB. Selections have at most 64 paths, each source file is bounded to 8 MiB, repository tree/index projections to 8192 entries, message to 8 KiB, captured output to 64 KiB and execution to 60 seconds, additionally clamped to the source Run's configured ceilings. Bounds and native relation failures fail before dispatch or retain a conservative unknown intent after a physical effect.

The dedicated verification artifact records the focused tests. They use actual Engine approval/verification pipelines, temporary Git repositories, a genuine supervisor, real hook failures and process groups, real SQLite trigger failures, actual SIGKILL before and after commit, archive export/import and independently forged native history. Existing verification, owned-command inbox and command-settlement regressions are included. Aggregate whole-repository validation belongs to the integration parent after the feature patch is applied.
