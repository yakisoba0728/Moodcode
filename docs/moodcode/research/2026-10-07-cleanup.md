# Provider 종료 관측과 실행 결과

2026-10-07의 제한된 소스 검토 기록이다. OpenCode와 Codex는 아래 고정 checkout의 Git HEAD를 확인했다. upstream 실행·빌드·라이브 모델 호출은 하지 않았다. 원본 구현·프롬프트·테스트를 Moodcode에 복사하지 않았으며 최신 버전이나 제품 간 동일한 보장을 주장하지 않는다.

- OpenCode `4ac0d9c3d169bbe81d9570013effdda3fe24d36e`: [processor의 stream 수명 처리](https://github.com/anomalyco/opencode/blob/4ac0d9c3d169bbe81d9570013effdda3fe24d36e/packages/opencode/src/session/processor.ts#L656-L690)는 drain, interruption, retry와 마지막 cleanup을 연결한다. [cleanup의 도구 정산](https://github.com/anomalyco/opencode/blob/4ac0d9c3d169bbe81d9570013effdda3fe24d36e/packages/opencode/src/session/processor.ts#L585-L609)은 도구 완료를 제한 시간 동안 기다리고 남은 도구 part에 interruption 결과를 기록한다. 이 함수들을 targeted read했으며 저장소 전체의 종료 보장을 검증한 것은 아니다.
- Codex `0b863c69f50335acd92164aab971cb58d298c2fe`: [task 취소](https://github.com/openai/codex/blob/0b863c69f50335acd92164aab971cb58d298c2fe/codex-rs/core/src/tasks/mod.rs#L940-L970)는 cancellation token, 종료 대기, task abort와 abort hook을 순서대로 처리한다. [중단 이력 publication](https://github.com/openai/codex/blob/0b863c69f50335acd92164aab971cb58d298c2fe/codex-rs/core/src/tasks/mod.rs#L980-L989)은 marker 저장 뒤 rollout flush를 시도하며 flush 실패를 경고로 처리한다. [compaction 완료](https://github.com/openai/codex/blob/0b863c69f50335acd92164aab971cb58d298c2fe/codex-rs/core/src/compact.rs#L832-L854)는 provider의 완료 이벤트와 usage를 관측한다. 이 경로들의 의미는 Moodcode의 SQLite 원자적 cleanup receipt와 다르다.
- Pi는 `/tmp/moodcode-pi-context-reference-ae92585d3b3e/packages/agent/src/agent-loop.ts`의 로컬 발췌만 읽었다. [고정 SHA로 기록된 코드](https://github.com/earendil-works/pi/blob/ae92585d3b3e5f1e4b123d14a34314d826d8d9f5/packages/agent/src/agent-loop.ts#L402-L455)는 provider에 AbortSignal을 전달하고 `done`/`error`에서 최종 response 결과와 message 종료를 처리한다. 디렉터리명과 기존 provenance 문서는 해당 SHA를 가리키지만 Git 메타데이터가 없어 이번 검토에서 commit 일치를 독립적으로 확인하지 못했다.

Moodcode의 `attempt_cleanup`은 독립적으로 작성한 별도 계약이다. 호출 전에 owner·provider·요청 모델·context revision·정확한 `engine-turn-request-v1` SHA와 byte count를 고정한다. request SHA는 엔진 요청의 identity이며 provider의 HTTP body나 원격 서버 상태를 증명하지 않는다. 원문 요청과 이미지 bytes를 cleanup 행에 저장하지 않는다. `prepared`/`dispatched` intent와 `confirmed`/`uncertain`/`not-dispatched` 관측을 구분하며, 확인 증거는 등록된 provider iterator의 `next().done === true` 또는 `return().done === true`다. 누락·거부·timeout·미완료 return은 종료 확인으로 바꾸지 않는다.

출력, 모델 완료 이벤트, iterator 종료와 실행 결과는 별개다. 종료가 확인되어도 불완전한 출력이나 기존 `uncertain` outcome을 성공으로 바꾸지 않는다. cleanup 관측은 immutable terminal record와 v1/v2 audit로 원자적으로 저장한다. 오래된 Attempt 상태에서 종료 증거를 backfill하지 않는다. Summary ACK도 정확한 불변 증거에 대한 host 결정이며 cleanup 확인, checkpoint 활성화, provider 재호출이나 자동 실행 재개를 뜻하지 않는다. uncertain ordinary Attempt는 ACK 예외 대상이 아니다.

검토 중 overflow crash frontier를 로컬 SQLite로 재현했다. 정상 storage API로 `Turn: created`, `ordinary Attempt: failed`, `ordinary cleanup: confirmed`, `summary: uncertain`인 영구 기록을 만들고 close/reopen/startup recovery를 수행했다. 이후 Run과 Turn은 `interrupted`였고 ordinary Attempt와 cleanup은 그대로였다. 실행 uncertainty predicate는 false지만 summary predicate는 true이며 recovery preview가 `SUMMARY_OVERFLOW_BINDING_MISMATCH`로 막혔다. 실제 provider 호출이나 SIGKILL을 수행한 재현은 아니다. 원인 연결을 Turn에 기록하기 전 종료되는 경계를 저장 계약 수준에서 모델링한 결과다.

루트의 `11da986`은 exact latest failed Attempt, 0개 Parts, 동일 owner/provider/model/context, 확인된 overflow cleanup과 해시·시간 순서를 유지한 `interrupted` source origin을 처리한다. summary usage commit과 uncertain settlement 직후의 두 실제 SIGKILL 검사가 통과했다. 이미지 wrapper의 `done` truthiness도 `done === true`로 수정하고 잘못된 nonboolean 완료의 regression을 확인했다. 실제 검증 범위와 전체 gate는 [최종 검증 기록](../engine-goal-verification.md)을 따른다.

조회 제한은 범위별로 읽어야 한다. 선택된 Turn payload 합계는 8MiB이고 ACK 증거에는 별도 한도가 적용된다. 두 제한을 전체 predicate의 합산 8MiB 보장이나 물리 SQLite I/O 상한으로 표현하지 않는다.
