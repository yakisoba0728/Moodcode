# 2026-10-07 이미지 입력 전송 조사

2026-10-07에 아래 공식 문서를 실제 열어 확인했다. 계정 인증, API 요청, 모델 실행 또는 실제 Codex 토큰 읽기는 하지 않았다. 문서의 요청 형태를 참고하고 Moodcode의 port와 검증은 독립 구현했다. fixture는 자체 작성한 합성 bytes와 mock HTTP이며 실제 모델 지원의 증거가 아니다.

| 공식 자료 | 확인한 전송 형태 | Moodcode 결정 |
| --- | --- | --- |
| [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision) | Responses user content의 `input_image`, `image_url`에 MIME을 포함한 base64 data URL; PNG/JPEG/WebP/정적 GIF | local bytes를 검증한 뒤 data URL로 변환; `detail: auto`; 원격 URL 및 Files API ID 입력은 받지 않음 |
| [OpenAI Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) | user content의 `image_url` part, 내부 `image_url.url` 및 optional detail | 동일 bytes를 MIME data URL로 변환; 이미지 없는 기존 string content는 유지 |
| [Anthropic Vision](https://platform.claude.com/docs/en/build-with-claude/vision) | user content의 `image`, `source.type: base64`, `source.media_type`, `source.data`; JPEG/PNG/GIF/WebP | canonical base64와 정확한 MIME 전송; 이미지 block을 text 앞에 배치 |

API 문서의 이미지 개수·payload 한도와 Moodcode의 초기 보호 예산은 구분한다. Moodcode는 이미지당 512 KiB, dispatch당 4개/decoded bytes 1 MiB, 세션당 32개/16 MiB를 사용한다. 이는 inline base64의 증가량, 기존 2 MiB request ceiling, 반복 전송 시 메모리·디스크 사용을 제한하려는 자체 정책이다. 모델별 context window, image token 계산 또는 vendor 최대치를 주장하지 않는다. 특히 입력 이미지 bytes는 text token과 같은 비율로 추정할 수 없다.

공통 구현은 정적 이미지에 한정한다. GIF의 추가 frame, PNG animation chunk, WebP animation flag/chunk를 거부한다. 로컬에서 pixel decode, resize, EXIF 적용, OCR, 임의 decoder 실행 또는 remote fetch를 수행하지 않는다. MIME magic, bounded container 구조와 선언 dimensions를 확인하며 완전한 decoder 검증이라고 주장하지 않는다. PNG CRC/압축 payload, JPEG entropy 및 WebP bitstream의 전체 유효성은 이 계층이 검증하지 않는다.

Codex adapter는 고정 endpoint와 기존 Responses delegate를 유지하며 같은 image encoding을 통과시킨다. Codex 전용 endpoint의 실제 이미지 지원이나 계정별 접근 권한은 이번 조사로 검증되지 않았다. adapter `inputModalities`는 encoding 구현 범위를 뜻하며 특정 모델 capability를 증명하지 않는다. 모든 provider의 image/audio/video 출력은 여전히 미지원이다.

원문 bytes와 base64는 image store 및 dispatch 직전 request에만 존재한다. SQLite 입력/Run/message/context/journal에는 immutable reference만 넣는다. 공개 reasoning summary와 encrypted native replay의 기존 경계는 바꾸지 않는다. 새 replay에 이미지 출력이나 raw image가 들어가도록 확장하지 않는다.
