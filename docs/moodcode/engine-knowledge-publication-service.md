# Explicit workspace document publication

`KnowledgePublicationService` implements the MC2-03c host approval boundary for SQL workspace documents. A preview contains the complete immutable candidate, original plan, completed native generation and attempt, historical trust revision, exact current document head/revision, before/after text, hashes and original expiry. Each preview is frozen and owned by one service through a WeakMap. Copies, proxies, another service's previews, released previews and operation reflection confer no approval.

Publication requires `approved: true` and the original preview. Ordinary input and budget data are detached before the workspace lease awaits. The service then rechecks the actual candidate/native tuple, workspace/database binding, import pause, exact document head, current approved trust and physical sources. Native `commit` calls the service's synchronous `assertCommitCurrent` inside its real transaction before the document CAS. The callback accepts only the service's active original preview context. Native storage derives text from the actual stored candidate and commits the publication, document revision, head and receipt atomically.

The candidate must already be linked by the generation's immutable `recorded` marker. A candidate append followed by a crash before that marker requires explicit candidate finishing before a publication preview can be issued. This prevents later marker changes from invalidating a published generation hash. Historical producer validation uses the stored generation/attempt/plan/candidate tuple and actual cleanup; it does not call `generation.readEvidence`, whose original target preimage intentionally becomes stale after publication.

Every publish or revoke advances the workspace document revision. Revocation approves the exact currently active publication and head, then commits a new empty revision with `sha256('')`. Current source staleness or a newer deny trust revision does not prevent this authority-reducing removal. Original binding, historical producer, unpaused workspace, active publication and head pins still must match. Revocation never resets the document to absent revision zero.

An exact duplicate observes the original durable publication/document/head/receipt before source freshness or a new lease; the historical head does not activate or overwrite the current head. A consumed preview cannot authorize a different request. Preview expiry is at most five minutes; publication also honors the original candidate/trust expiry. The operation's independent duration defaults to five seconds and cannot exceed thirty seconds. Cancellation or duration expiry while waiting for a lease returns boundedly, and the late callback checks cancellation before preparing any native owner. Cancellation after an actual native commit preserves its observed receipt.

The service bounds complete preview bytes to 256 KiB, preview handles to 128 and simultaneous operation reservations to 32. No provider, tool, coding Session or Run is created. Filesystem targets remain typed unsupported. Engine opt-in, DB12/archive integration and actual crash tests are separate integration owners; active ContextPlan consumption belongs to MC2-03d and is not established by this service.

The service fixtures use real SQLite transactions, actual Git/FS source captures, the native generation streamer and native publication storage. Deferred-lease and callback seams test immutable inputs, deadlines, cancellation and revalidation without fabricating successful database records. Actual Engine and SIGKILL fixtures independently exercise the integrated host boundary.
